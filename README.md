# looksmax-cli

A terminal dashboard (plus a live camera preview window) that analyzes your
face in real time through your webcam and displays a set of geometric
measurements plus a composite score, styled after the informal "PSL" scale
used in online looksmaxxing communities — right there on your screen, live.

## Disclaimer

**This is a for-fun engineering/portfolio project, not a medical, psychological,
or scientific tool.**

- The metrics and the composite score are based on an informal, non-validated
  scoring system borrowed from online communities. They have no clinical or
  scientific basis.
- The result is **not** an objective evaluation of anyone's appearance and
  should not be taken seriously.
- There is no history, progress tracking, day-to-day comparison, or
  sharing/social feature, by design — this tool only ever shows you a live,
  in-the-moment snapshot. It does not save frames, video, or metrics to disk
  by default.
- Everything runs fully offline, on your machine. No frame or measurement is
  ever sent to any external API or service.

This disclaimer is also printed every time you start the CLI.

## How it works

Two processes talk to each other over stdout/stdin, using one JSON object
per line — no external broker, no network:

1. **Python CV worker** (`cv_worker/face_worker.py`) captures webcam frames
   with OpenCV, runs MediaPipe Face Mesh to find facial landmarks, computes a
   handful of raw geometric metrics per frame, smooths them over time, and
   streams them to stdout. Unless `--no-preview` is passed, it also opens a
   live OpenCV window with the mirrored feed and the heuristics drawn on top
   (canthal tilt, jaw lines, cheekbone/temple width, facial thirds, the
   profile silhouette, and the composite score) — purely visual, it doesn't
   affect the JSON stream.
2. **Go core** (`core/`) launches the worker as a subprocess, parses its
   output, computes a weighted composite score from the raw metrics, and
   renders a live dashboard with [Bubble Tea](https://github.com/charmbracelet/bubbletea)
   and [Lipgloss](https://github.com/charmbracelet/lipgloss).

Running the Go binary currently launches *both* surfaces at once: the
terminal dashboard, and the Python worker's own preview window (since the Go
side doesn't pass `--no-preview` through). See
[Known limitations](#known-limitations).

## How scoring works (read this before taking it seriously)

The composite score and the raw metrics are all **heuristics**, not
measurements grounded in any peer-reviewed research:

- Landmarks come from MediaPipe Face Mesh, a general-purpose face-mesh model
  — not a clinical anthropometry tool. The metrics below reuse its landmark
  indices as rough stand-ins for anatomical points (e.g. "gonion" or facial
  thirds), since exact clinical landmarks aren't reliably detectable from a
  single webcam frame.
- The composite score is a hand-picked weighted formula (see
  `core/tiers.go`) that compares each raw metric against an arbitrary
  "ideal" target and tolerance, then blends the results. Both the weights
  and the targets are subjective opinions loosely inspired by looksmaxxing
  community lore, not derived from any study.
- The tier thresholds (`Subhuman`, `LTN`, `MTN`, `HTN`, `Chadlite`, `Chad`)
  are also informal community conventions, reproduced here purely for
  entertainment/nostalgia value.

In short: treat every number this tool prints as a subjective, for-fun
opinion generated by a small pile of trigonometry — not a fact about you.

### Raw metrics

| Metric | What it approximates |
|---|---|
| `symmetry` | 0-100 score comparing mirrored landmark pairs against the face's midline axis (100 = perfectly symmetric) |
| `canthal_tilt_deg` | Angle of the inner-to-outer eye-corner line vs. horizontal, averaged over both eyes |
| `gonial_angle_deg` | Approximate mandible (jaw) angle, using temple/cheek and chin landmarks as stand-ins for the true cephalometric points |
| `bigonial_width_ratio` | Jaw width relative to face height (forehead-to-chin) |
| `cheekbone_ratio` | Cheekbone width relative to overall (temple-to-temple) face width |
| `facial_thirds_dev` | How unevenly the brow-nose / nose-lip / lip-chin segments are sized, as a % deviation from perfect thirds |
| `facial_convexity_deg` | Profile angle at the nose tip between the glabella and the chin — reads best in profile, collapses toward ~180° (a flat line) near-frontal |
| `nasofrontal_angle_deg` | Profile angle at the nasion (nose bridge) between the forehead and the nasal dorsum — same profile-only caveat |
| `nasolabial_angle_deg` | Profile angle at the nose base between the columella and the upper lip — same profile-only caveat |
| `frontality_offset` | How far off-center the nose tip sits, as a fraction of face width (~0 = frontal, grows toward profile). Used to decide whether the composite score can be trusted for the current frame — see below |

Note the split: `symmetry`, `gonial_angle_deg`, `bigonial_width_ratio`, and
`cheekbone_ratio` need a roughly **frontal** face (they compare left/right
landmark pairs); `facial_convexity_deg`, `nasofrontal_angle_deg`, and
`nasolabial_angle_deg` need a roughly **profile** face (they measure a
silhouette that's nearly a straight line head-on). No single pose gives you
every metric at once.

### Temporal smoothing

Every metric is passed through an exponential moving average (`α = 0.35`,
see `MetricsSmoother` in `face_worker.py`) before it's displayed or emitted,
to cut down frame-to-frame jitter — worst at extreme head angles, where
MediaPipe's landmark predictions are least confident. It resets whenever
face detection drops out, so it never blends two unrelated sightings.

### Composite-score pose gating

The composite score/tier is only shown when `frontality_offset` is at or
below `0.22` (`maxFrontalityOffsetForScore` in `core/tiers.go`, mirrored as
`_FRONTALITY_MAX` in `face_worker.py` — keep both in sync if you tune it).
Past that threshold, several of the metrics feeding the score are being
computed on a face pose they weren't designed for (see the split above),
so both the TUI and the preview window show "turn face frontal to rate"
instead of a confident-looking but meaningless number.

## Installation

### Prerequisites

- Go 1.22+
- **Python 3.11** with `pip` (MediaPipe's legacy `mp.solutions.face_mesh` API,
  which this project depends on, was dropped from wheels somewhere around
  `mediapipe==0.10.10`+; `requirements.txt` pins `mediapipe==0.10.9`, the last
  version that still ships it. Python 3.13 doesn't have a compatible wheel at
  all — use 3.11.)
- A webcam

### Set up the CV worker

```bash
cd cv_worker
python3.11 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### Build the Go core

```bash
cd core
go build -o looksmax-cli .
```

## Usage

Run from the `core/` directory (or point `--python-path` at the venv
interpreter you created above):

```bash
./looksmax-cli --python-path ../cv_worker/.venv/bin/python3
```

### Flags

| Flag | Default | Description |
|---|---|---|
| `--python-path` | `python3` | Path to the Python interpreter used to run the CV worker |
| `--camera-index` | `0` | OpenCV camera device index to capture from |
| `--no-color` | `false` | Disable colored output |
| `--metrics-only` | `false` | Show only the raw metrics, without the composite score/tier |
| `--config` | *(none)* | Optional YAML file overriding the composite-score weights (see below) |

Press `q` or `Ctrl+C` to quit; the CV worker subprocess is shut down
gracefully on exit. To close just the preview window, press `q`/`Esc` in it
or click its close button — this also stops the whole worker (and, with it,
the Go TUI's metrics feed).

### Running the CV worker directly

You can also run `cv_worker/face_worker.py` on its own — useful for just
watching the preview window without the terminal dashboard:

```bash
cd cv_worker
source .venv/bin/activate
python face_worker.py --camera-index 0
```

| Flag | Default | Description |
|---|---|---|
| `--camera-index` | `0` | OpenCV camera device index to capture from |
| `--no-preview` | `false` | Disable the live preview window; stream JSON metrics only |

When run this way from a real terminal with the preview window on, the
JSON-lines stream is automatically suppressed (nothing to scroll behind the
window for); redirect stdout to a file/pipe (as the Go core does) and it
streams normally regardless of the preview flag.

### Optional score-weight config

By default, the weights used to combine raw metrics into the composite
score are fixed constants in `core/tiers.go`. If you want to experiment
with the calibration, pass a YAML file via `--config`:

```yaml
# weights.yaml — values are re-normalized to sum to 1.0 automatically
weights:
  symmetry: 0.25
  canthal_tilt: 0.15
  gonial_angle: 0.15
  bigonial_width: 0.15
  cheekbone: 0.15
  facial_thirds: 0.15
```

```bash
./looksmax-cli --config weights.yaml
```

This file is never written to automatically and nothing is persisted
between runs.

## Known limitations

- **No `--no-preview` passthrough from the Go core yet.** Running
  `looksmax-cli` always launches the Python worker with its preview window
  on; there's no Go flag to suppress it yet. If you want the TUI without
  the extra window, that's a small addition to `main.go` (pass
  `--no-preview` through to the worker command) — not yet implemented.
- **MediaPipe Face Mesh degrades at extreme head angles.** It's trained
  mostly on near-frontal faces; close to true profile (~90° yaw) it starts
  filling in occluded landmarks from its training statistics rather than
  truly tracking them, which can look like a generic mesh "sliding" over
  the face rather than following the real bone structure, plus more
  frame-to-frame jitter (partially offset by the smoothing described
  above, but not eliminated).
- **Everything here assumes a single, cooperative, well-lit face.** No
  multi-face handling, no low-light compensation, no camera calibration.
